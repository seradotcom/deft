# REPORT — DEFT (Computer-Use Automation System)

> **The model discovers. The capability replays.**
> One design principle threads through every layer: **degradation is explicit,
> never silent.** Targeting, extraction, tenancy, recovery and escalation all
> say exactly how sure they are — and the artifact ages on evidence, not on
> silence.

The target surface is **LegacyBank** (`src/targets/legacybank`), a hostile
simulator of the real problem: two tenants (ACME FCU / NorthWind CU) running
the same vendor product ("CoreVision Suite") configured differently —
server-rendered `<frameset>` shell, table layouts, WebForms-style autogenerated
controls (`ctl00$ContentPlaceHolder1$...`), no test IDs, native `window.confirm`
on the irreversible step, session timeouts, and a deterministic fault-injection
endpoint for evidence runs. Everything below was executed against it; the
curated bundles are in `/evidence`.

## 1. Architecture

Single process, five ports, CLI as the face of the system. Simplicity was a
deliberate call: no queues, no services — the *boundaries* are the design, not
the deployment.

```
CLI ──▶ Discovery (LLM in loop, once)          CLI ──▶ Replay Engine (no model, always)
         │ observe→decide→act→record            │ locate→act→verify per step
         ▼                                      ▼
      SurfaceDriver ◀──── same port ─────▶ PolicyEngine (allowlist, risk)
      (Playwright impl;                    EvidenceLogger (JSONL + shots, redacted)
       desktop = same port)                EscalationManager ⇄ Operator Console
```

Key decisions and why:

- **Record-time *verified* targeting (the core idea).** Most record/replay
  systems store what the driver happened to click. DEFT marks the element with
  a temporary attribute, *probes candidate semantic locators live* (role/name →
  label → placeholder → title → vendor `name` attr → id → coordinate), and
  keeps only candidates whose first match **is the marked element**. The stored
  descriptor is therefore *proven*, with a recorded `quality`
  (`verified | partial | coordinate-only`) and a fingerprint (tag, normalized
  id pattern, accessible name, ordinal) that replay re-verifies with a
  similarity score. This is the answer to "locator robustness": not a smarter
  string, a verification protocol.
- **Hybrid observation.** The planner sees the screenshot *and* an
  accessibility outline annotated with stable `[eN]` refs, and may act by
  element ref or by 0–999 grid coordinates. Semantics when they exist; vision
  when they don't — which is precisely the legacy-app condition. The action IR
  is modality-agnostic, so a desktop driver (UIA) implements the same port.
- **Compilation is a first-class, re-runnable step** (transcript → artifact),
  with judgment encoded and documented: login steps are auto-detected and
  parameterized to environment bindings; typed input values replace matching
  literals; model-proposed outputs become *relational* table extractors via a
  reverse cell lookup; submit/confirm controls get `riskClass: risky` by name
  heuristic; the artifact ships as `draft` for human review. The compiler
  refuses to silently drop unresolvable steps — integrity over convenience.
- **Gemini function calling** with the unglamorous parts done right:
  `thoughtSignature` round-tripping (required by Gemini 3.x or the API 400s),
  history pruning of old screenshots to respect request limits, and 429
  backoff honoring `retryDelay` — free-tier rate limits are a *runtime
  condition*, not an error path.

Trade-off worth naming: replay resolves locators through Playwright directly
(escape hatch on the driver port) rather than through a fully abstract
"resolution context". A desktop driver would expose its own; the seam is
documented where it exists.

## 2. Artifact schema

`src/core/artifact.ts` — zod is the single source of truth: static types,
runtime validation, and a reviewable JSON contract from one definition.

Shaped by five decisions:

1. **JSON Schema (draft 2020-12) for `inputs`/`outputs`** — any agent or human
   can validate a call without our code. The artifact *is* the caller's
   contract.
2. **Steps carry a human `intent`** ("Enter operator password") next to the
   machine fields — a reviewer reads the flow without decoding descriptors.
3. **Values are always templates into declared inputs** (`{{inputs.memberId}}`)
   or environment bindings (`{{env.password}}`, marked sensitive). Captured
   PII cannot leak through a value field because values *are* references —
   redaction by construction, not by scrubbing.
4. **Business outcomes are declarative data**, not buried conditionals:
   `businessOutcomes[]` with detection patterns (`pageTextContains`,
   `dialogTextContains`, `urlGlob`) and `returnsToCaller` payloads. The
   most common design failure in this domain — conflating "no such member"
   with a crash — is here a first-class, reviewable declaration.
5. **Targeting is a chain with honest metadata**:
   `primary` (always semantic) → `fallbacks` (weaker semantics → legacy
   `name`/`id` → coordinate as explicit last resort) + `fingerprint` +
   `quality` + a `rationale` string explaining what was verified and how.

Also in the schema: `recoveryChains` (named, shared action chains referenced by
steps via `chainRef` — recovery logic without per-step bloat), `variants[]`
(tenant overlays as flat-key patches), and `provenance.validation` — the
artifact records its own replay health (success/failure counts, last status)
and flips `draft → approved` after repeated clean replays, or `→ needs-review`
on degradation. The capability *ages on evidence*.

## 3. Determinism & error handling

**Determinism** comes from four rules: no model between steps; values only from
declared inputs/env; locators resolved through the verified chain with
fingerprint verification (strict-mode matches are a *signal*, never suppressed);
and waits that respect how legacy apps actually behave — `domcontentloaded`
plus a **frame-URL stability window**, because form flows are 302 chains and
DOM-ready fires on the empty redirect response (this exact race produced our
most instructive bug: steps ran one page behind).

**The result contract is three-way**, per the brief's central distinction:

- `SUCCESS` — checkpoints verified (frame-aware URL globs, element visibility,
  page text), typed outputs returned.
- `BUSINESS_OUTCOME` — a declared, expected answer. Evidence:
  replay with `memberId=M99999` returns
  `BUSINESS_OUTCOME / MEMBER_NOT_FOUND` — detection fires from the failure
  path *and* before a coordinate fallback would blind-click.
- `FAILED` — hard stop with `{stepId, phase: locate|act|verify, errorClass,
  expected, observed, evidenceRefs}` — enough to debug without re-running.

**Recoverable conditions** are bounded, per-step, auditable chains
(`maxAttempts ≤ 3`, every attempt in evidence). The flagship: session expiry
mid-flow. Legacy apps redirect the *frame* to login while the top URL never
moves — so recovery matches the redirect glob against **every frame URL**, then
runs a shared `relogin` chain (entry → credentials from env → submit), then
**fast-forwards the deterministic flow**: the verified steps between login and
the failed one are re-executed so POST-arrival pages are re-reached by re-running
the flow rather than by blind GET navigation (navigating straight to a
POST-arrival page yields "Cannot GET" — the screenshots taught us this). The
failed step is then retried through the same guarded executor. Evidence bundle
`replay-session-recovery/` shows the chain firing, the fast-forward, and the
run completing **SUCCESS** with the correct balance.

**Fail-closed geometry.** Frame resolution is strict: a step targeting a
frame path that no longer exists fails with `FRAME_NOT_FOUND` instead of
silently acting on a parent surface — the failure mode that made post-expiry
replays click the wrong screen. For the same reason, the recorded-coordinate
fallback is legal **only for clicks**; a `fill`/`select`/`press` whose only
resolution is a coordinate fails with `COORDINATE_FALLBACK_UNSUPPORTED` — a
coordinate is a point, not a control, and pretending otherwise produced silent
no-ops. Recorded coordinates carry their space explicitly (frame-local pixels).

**Policy is enforced per interaction, on the target surface.** Before every
interactive step, replay resolves the step's frame and polices *that frame's
URL* against the allowlist — the top-level URL of a frameset app never changes,
so policing it alone would be theatre. An interactive action on a frame that
redirected to a disallowed origin is blocked before any interaction
(`POLICY_BLOCKED`, integration-tested with a zero-click assertion).

**Drift** (the rarer case per the brief) is handled by honesty: if only the
coordinate fallback resolves, the step is marked `degraded` in the result; the
artifact's `provenance.validation` counts failures and degradations and flips
status to `needs-review`. Replay never silently "heals".

## 4. Heterogeneity & multi-tenant

**Surface abstraction.** Everything above `SurfaceDriver` (observe/act/
facts-at-point/probe) is surface-agnostic. The web driver implements it with
Playwright; a desktop driver would implement the same port over UIA with
window-relative coordinates — the observation format (screenshot + semantic
outline) and the action IR were chosen to survive that translation. What
*didn't* generalize cleanly is exposed as such: replay's locator resolution
uses a Playwright-specific context, an admitted seam.

**Legacy web.** The record-time probing was designed *for* hostile markup: on
the simulator it produces `verified` descriptors even for fields with no label,
no placeholder and autogenerated ids — because the vendor `name` attribute
(the postback key) and normalized id patterns (`ctl{N}_..._txt{D}`) are stable
per vendor version. Cross-frame targeting (framesets, iframes) is handled at
record time (frame path in the descriptor) and at replay time (frame-aware
checks everywhere: redirects, URL globs, page-text probes).

**Multi-tenant reuse is demonstrated, not just designed.** The lookup
capability was recorded on ACME and replayed on **NorthWind** — different
branding, different labels ("Sign In"→"Login", "Member Search"→"Members",
"Find Member"→"Search"), vendor version 2.4 — via a declarative variant
overlay (`variants[]` with flat-key patches, bracket keys resolving steps by
*id*, not position). Two mechanisms carried the replay, and both matter:
the overlay patched the tenant-specific labels, **and** the fallback chain's
vendor-stable `name` attributes matched even where labels moved. Evidence:
`replay-cross-tenant/` → SUCCESS, same balance. Drift management: fingerprint
mismatches at replay mark degradation and queue `needs-review`; per-tenant
failure counts would route re-recording — designed, intentionally not built
(see Cuts).

## 5. Escalation & handoff

The control-transfer model is a **lease**: exactly one controller
(`automation | human`) owns the live session at any moment, with explicit
take-over and resume — never both, never a fresh session.

Triggers: the model's own `ask_human` action (proactive escalation is a
first-class move, not just a timeout), unrecoverable replay failures, and —
the case banks actually care about — **risky steps**. Irreversible actions
are blocked unattended (`RISKY_STEP_BLOCKED`, evidence in `risky-gating/`);
with `--escalate`, the run raises an intervention and *waits*.

Mechanics: the automation loop parks on a promise; an `InterventionRequest`
(why, URL, screenshot, accessibility outline) appears on the **operator
console** (local HTTP, deliberately minimal); the operator works **the same
headed browser window** automation was driving — not a copy, not a mock-up of
co-browsing — then hits *Resume*. The loop re-observes and continues from the
actual state. While the lease is human, the engine **samples the live session** every
~1.5 s (screenshot + page-text hash, stored as `human_sample` evidence) —
the sample series is the audit record of what the operator did, and the result
contract reports `humanActionsObserved` alongside `resumedByHuman`. The
escalation callback receives the **real current observation** (screenshot +
accessibility outline), so the console card shows exactly what automation saw.

End-to-end evidence (`hitl-approval/`): the open-sub-account replay raises
"risky step requires operator approval" → takeover → approval → resume → the
native `window.confirm` is accepted and logged → run completes
`SUCCESS` with `resumedByHuman: true`. The same channel also approves risky
steps *in place* — approval is a decision, not a config flag.

Every replay result also carries the **sha256 of the exact artifact bytes it
executed**, and `evidence/manifest.json` ties each scenario to its run,
artifact hash, expected and actual outcome, and file list —
`npm run verify:submission` re-checks all of it automatically (provenance
chains, terminal statuses, referenced screenshots, duplicate runs, secrets).

## 6. Safety

- **Allowlist before action, in both loops.** `PolicyEngine` checks navigation
  targets and the current URL for interactive actions; out-of-policy proposals
  are fed back to the planner as blocked (discovery) or hard-fail
  (replay, `POLICY_BLOCKED`).
- **Risk is classified and enforced.** Steps that open/confirm/submit financial
  state are `risky`; unattended replay blocks them; approval comes only from
  `--allow-risky` (explicit) or a live operator decision (better).
- **Redaction at the sink.** Every evidence line and artifact passes through
  redaction: known secret values registered per run are replaced before
  serialization, sensitive keys never persist values, and regex patterns catch
  SSN/card/amount shapes. Artifacts go further: credential *values* cannot be
  stored because login steps template into `{{env.*}}` bindings by
  construction.
- **Ground rules respected**: local simulator only, no external sites, demo
  credentials in `.env` (git-ignored) and still redacted everywhere.

Limits, stated plainly: the redactor is pattern-based (a novel secret format
typed into a non-sensitive-looking field could slip into a discovery
transcript — the artifact compiler is the second line, since values template
into inputs); the allowlist is prefix-based (no per-route verbs); and the
operator console is localhost-only with no authentication — acceptable for a
single-operator demo, a real deployment would broker identities.

## 7. Cuts

What we deliberately left out, and what we'd build next:

1. **Discovery-time risk classification.** Replay enforces risk hard
   (`RISKY_STEP_BLOCKED` / operator approval), but during *discovery* the
   risky heuristic is applied at compile time — after the model already acted —
   and in-loop safety is prompt-guided plus action-type allowlisting. A
   production system would run the risk classifier against the resolved target
   *before* the side effect, routing to a human pre-execution. Next: move the
   compile-time heuristic in front of the act call during discovery.
2. **Desktop driver.** The port and IR were shaped for it (coordinates,
   semantic outline); no UIA implementation. Next: a Windows UIA driver behind
   the same port, reusing the entire record/verify/compile stack.
3. **Cross-tenant drift telemetry.** Variant overlays work; the *management*
   of drift across hundreds of tenants (failure clustering → which tenant
   variant needs re-record; confidence scoring per tenant) is designed into
   `provenance.validation` but not aggregated anywhere. Next: a nightly replay
   sampler feeding the needs-review queue.
4. **Capability catalog / agent-facing API.** The stretch goal: expose
   approved capabilities as a typed tool surface (list + invoke by name). The
   artifact schema already *is* the tool schema; only the serving layer is
   missing.
5. **Operator console polish.** It is deliberately a minimal lease-transfer
   surface (context, takeover, resume, abort, audit). A production console
   would add live view, role separation, and intervention queues per team.
6. **Multi-run stability scoring.** Replaying N times to emit a flakiness
   signal — the plumbing (validation counters) exists; the N-run harness
   doesn't.
